# Prospective backend lifecycle repair

These are exact reviewed copies of `backend-v2.py`, its 33 synthetic offline
controls and the frozen method note. Their hashes are listed in the separate
`../M6-INFRASTRUCTURE-SUPPLEMENT-SHA256.json`. The original 32 tools and their
public manifest in `../tools/` remain unchanged.

The repair checks a client's loaded execution identity separately from the
lifetime of its cgroup. An owned successful exited client may supply genuine
retained systemd `MemoryPeak` only after its concrete former cgroup paths have
disappeared and a fresh identity check succeeds. A running client, anchor,
parent or server still needs its live counters. Missing files in an existing
group, permissions errors, zero/unknown peaks and foreign executions refuse.
Failed-cleanup absence handling cannot create valid measured workload evidence.

The method and test source record author-run pure controls; copying these files
did not execute them, launch a process or collect a new native measurement.
Their presence does not qualify the interrupted cohort or establish a speed,
memory or content result. A new registration must bind this helper before any
new cohort starts, retaining all original workload and acceptance requirements.

Executable sources retain the generic benchmark cache namespace, standard
system/container paths and image/tool pins needed for reproduction. Tests use
synthetic repeated-character identities, dummy process values and a deliberately
fake credential-like error string. None is a captured session, capability,
private runtime identity or generated environment. Actual configs, state,
cookies, environment files, media, private closures and logs are not included.

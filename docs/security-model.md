# Security model and operational limits

This MVP handles untrusted URLs and media. The engine includes application protections, and deployment provides another boundary.

## Network

- User source links require HTTPS on port 443, no URL credentials and bounded length. Only recognized platform page hosts may upgrade HTTP/schemeless pastes; unknown/direct signed queries remain unchanged.
- The HTTP client disables environment proxies, resolves all host addresses, rejects private/reserved/loopback/link-local/multicast and transition ranges, then dials a validated IP directly. DNS rebinding cannot change that connection's destination. Redirects are rechecked and HTTPS downgrades are refused.
- Upstream HTTP response headers are limited to 64 KiB instead of the transport's 10 MiB default, independently of media/thumbnail body budgets.
- DNS resolution and all ordered address fallbacks share a 15-second deadline; each attempt receives a bounded share of the remaining time, and an earlier request deadline wins. Fully consumed responses reuse connections, while interrupted responses are closed without draining the remaining video. Relay buffers reuse fixed 32 KiB arrays and keep the aggregate transfer accounting. Closing a guard cancels active relay requests and both directions of hijacked CONNECT tunnels; new attempts do not bypass address validation or replay POST requests.
- yt-dlp extraction is configured with an authenticated loopback proxy. The proxy validates/pins each upstream destination, including CONNECT. Plugins, user configuration, remote components, and exec hooks are not enabled. The bundled EJS solver and Node runtime are used.
- Supported progressive platform media passes through opaque loopback relay registrations, not arbitrary caller-supplied relay URLs. Every range fetch uses the same guarded HTTP client and the job transfer budget.
- Finite HLS is parsed by Go, with bounded size, nesting, variants, segment count/durations and a mandatory completed media playlist. Each selected segment, relative URL, init map and redirect uses the same public-IP-pinned HTTPS client and aggregate job budget. Encrypted keys and unsupported tags/rendition clocks fail explicitly; no key URL is fetched. Only bounded selected media bytes are staged and remuxed locally.
- FFmpeg/ffprobe input protocol and demuxer allowlists refuse untrusted playlists/network manifests and arbitrary format protocols. Local inputs permit the file protocol; remote media inputs permit HTTP/TCP to the relay and an explicit media-container allowlist. MOV external data references are not enabled.

The proxy settings are a contract with yt-dlp, not an OS-level network sandbox. An extractor/runtime vulnerability or upstream behavior that ignores the configured proxy is outside this application boundary. Public deployments should additionally restrict container egress to prevent access to internal service/metadata ranges. Run containers without privileges; mount only necessary media data. Keep dependencies updated.

## Ownership and browser requests

- A random 256-bit HttpOnly SameSite cookie acts as an anonymous capability. Only its SHA-256 ownership hash is stored.
- Every source/job/media/thumbnail/artifact lookup includes the owner. Cross-owner resources return 404. Capability cookies can be generated by clients; this does not grant access to another random owner.
- Per-client-IP mutation limits apply independently of session creation; changing cookies cannot bypass those limits. Authenticated reads and mutations also share a generous 1,200-request/minute IP ceiling, before per-owner state is allocated, so cookie rotation cannot create unlimited lookup traffic. Shared networks share IP limits. The rate table is capped at 10,000 entries; existing entries retain their own allowances at capacity, and expiry scans run at most once per second rather than on every blocked request. Global queue admission and source/worker resource bounds also apply.
- JSON bodies have a separate ten-second read deadline (or an earlier request deadline); incomplete/invalid HTTP/1 JSON requests close their connection. All handlers terminate leftover-body draining on return, including rejected uploads and early session/origin/rate failures; GET/HEAD bodies are rejected. The longer bounded media-upload window still applies to accepted uploads.
- Origin checks and Fetch Metadata reject cross-site mutations. Set an exact public origin and secure cookies behind HTTPS.
- Trust forwarded IPs only on an internal API behind a trusted proxy that normalizes the header. Never expose that API directly with `TRUST_PROXY=true`.
- Thumbnails are staged within 2 MiB and inspected as PNG/JPEG with bounded dimensions. Clients receive an owner-protected endpoint, never raw CDN thumbnail links; source cleanup also removes thumbnail files.
- Media MIME is sniffed from bytes and constrained to media or octet-stream, not inferred from user filenames. Downloads set attachment disposition and responses use nosniff.

## Processing and persistence

- Media commands use fixed arguments, never a shell or user-provided command fragments. Context cancellation terminates Unix process groups. Output bytes, duration, transfer bytes, time and FFmpeg threads are bounded. HLS import requires measured full-manifest duration to agree with provider metadata within 1 second. Local remux presentation offsets preserve the original timeline and A/V delay; separate HLS renditions are refused rather than assuming synchronisation.
- Worker leases expire; stale workers cannot update state or register artifacts after takeover. Shutdown/lost lease access leave unfinished work recoverable within the existing attempt limit, including interruption during publication; completed outputs are retained. User cancellation wins concurrent failures for pending items. Final database reads/writes have five-second bounds.
- The independent worker health command checks a private, empty local temporary marker refreshed only after successful queue claims/idle queries or active lease heartbeats. It resets on startup, expires after 30 seconds and is removed on shutdown. Do not put this marker on shared media storage.
- Export item error codes and messages use fixed public diagnostics. Subprocess stderr remains private; unknown failures do not invent retry causes or authorize automatic media retries. Stream selection ranks only complete supported input pairs; unsupported separate HLS clocks remain refused.
- Artifacts and sources expire through worker cleanup. Active jobs pin resources. Terminal jobs without retained artifacts are removed, allowing source cleanup. Temporary workspaces from crashed workers are reclaimed after retention/time limits.
- Limits in this release assume one API and one worker. They are admission limits, not a filesystem quota: apply a real volume/disk quota and memory/CPU/PID limits too. The production Compose API and worker drop all capabilities and use a read-only root filesystem, a writable media volume, and a bounded 128 MiB non-executable temporary filesystem. Both have PID limits. Leave room for PostgreSQL, logs, and operating-system updates.
- Old unregistered artifact/source files left by a crash between disk publication and database registration are reconciled against database paths. A timeout/retention floor prevents cleanup from racing active writes. Normal errors remove unregistered files immediately.

Do not log session cookies, signed CDN links, passwords, or raw subprocess output in public responses. Sensitive data should not be committed to this repository. See [SECURITY.md](../SECURITY.md) for reporting.

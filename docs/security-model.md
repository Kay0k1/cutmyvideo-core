# Security model and operational limits

The engine handles untrusted URLs and media. The engine includes application protections, and deployment provides another boundary.

## Network

- User source links require HTTPS on port 443, no URL credentials and bounded length. Only recognized platform page hosts may upgrade HTTP/schemeless pastes; unknown/direct signed queries remain unchanged.
- The HTTP client disables environment proxies, resolves all host addresses, rejects private/reserved/loopback/link-local/multicast and transition ranges, then dials a validated IP directly. DNS rebinding cannot change that connection's destination. Redirects are rechecked and HTTPS downgrades are refused.
- Upstream HTTP response headers are limited to 64 KiB instead of the transport's 10 MiB default, independently of media/thumbnail body budgets.
- The loopback proxy caps request headers at 32 KiB. Relay registration copies caller headers; later mutation cannot change a registered stream. Encoded upstream representations retain Content-Encoding/Vary when forwarded.
- The address denylist also covers deprecated IPv4-compatible/site-local IPv6, discard/dummy/benchmark/ORCHIDv1, documentation and SRv6 special ranges. IPv4-mapped addresses are checked as IPv4; currently public IETF assignments are not blanket-blocked. Registry references: [IANA IPv4](https://www.iana.org/assignments/iana-ipv4-special-registry), [IANA IPv6](https://www.iana.org/assignments/iana-ipv6-special-registry).
- DNS resolution and all ordered address fallbacks share a 15-second deadline; each attempt receives a bounded share of the remaining time, and an earlier request deadline wins. Fully consumed responses reuse connections, while interrupted responses are closed without draining the remaining video. Relay buffers reuse fixed 32 KiB arrays and keep the aggregate transfer accounting. Closing a guard cancels active relay requests and both directions of hijacked CONNECT tunnels; new attempts do not bypass address validation or replay POST requests.
- yt-dlp extraction is configured with an authenticated loopback proxy. The proxy validates/pins each upstream destination, including CONNECT. Plugins, user configuration, remote components, and exec hooks are not enabled. The bundled EJS solver and Node runtime are used.
- Supported progressive platform media passes through opaque loopback relay registrations, not arbitrary caller-supplied relay URLs. Every range fetch uses the same guarded HTTP client and the job transfer budget.
- Finite HLS is parsed by Go, with bounded size, nesting, variants, segment count/durations and a mandatory completed media playlist. Each selected segment, relative URL, init map and redirect uses the same public-IP-pinned HTTPS client and aggregate job budget. Encrypted keys and unsupported tags/rendition clocks fail explicitly; no key URL is fetched. Only bounded selected media bytes are staged and remuxed locally.
- FFmpeg/ffprobe input protocol and demuxer allowlists refuse untrusted playlists/network manifests and arbitrary format protocols. Local inputs permit the file protocol; remote media inputs permit HTTP/TCP to the relay and an explicit media-container allowlist. MOV external data references are not enabled.

The proxy settings are a contract with yt-dlp. Public deployments should add an independent container/host egress policy: allow the service's own PostgreSQL, public DNS and public HTTPS, and refuse private/metadata destinations and other outbound ports. The standalone Compose example does not install that firewall; configure and verify it separately, including after Docker/host restarts. See the independent [operator guide](operations.md), and keep dependencies updated.

## Ownership and browser requests

- A random 256-bit HttpOnly SameSite cookie acts as an anonymous capability. Only its SHA-256 ownership hash is stored.
- Every source/job/media/thumbnail/artifact lookup includes the owner. Cross-owner resources return 404. Capability cookies can be generated by clients; this does not grant access to another random owner.
- Per-client-IP mutation limits apply independently of session creation; changing cookies cannot bypass those limits. Authenticated reads and mutations also share a generous 1,200-request/minute IP ceiling, before per-owner state is allocated, so cookie rotation cannot create unlimited lookup traffic. Shared networks share IP limits. The rate table is capped at 10,000 entries; existing entries retain their own allowances at capacity, and expiry scans run at most once per second rather than on every blocked request. Global queue admission and source/worker resource bounds also apply.
- JSON bodies have a separate ten-second read deadline (or an earlier request deadline); incomplete/invalid HTTP/1 JSON requests close their connection. Responses with unread bodies disable HTTP/1 connection reuse before committing headers and stop leftover-body draining, including rejected uploads and early session/origin/rate failures; GET/HEAD bodies are rejected. Fully consumed JSON and multipart bodies clear their read deadline without cancelling the connection context used by later requests. The longer bounded media-upload window still applies to accepted uploads.
- Origin checks and Fetch Metadata reject cross-site mutations. Set an exact public origin and secure cookies behind HTTPS.
- Trust forwarded IPs only on an internal API behind a trusted proxy that normalizes the header. Never expose that API directly with `TRUST_PROXY=true`.
- Thumbnails are staged within 2 MiB and inspected as PNG/JPEG with bounded dimensions. Clients receive an owner-protected endpoint, never raw CDN thumbnail links; source cleanup also removes thumbnail files.
- Media MIME is sniffed from bytes and constrained to media or octet-stream, not inferred from user filenames. Downloads set attachment disposition and responses use nosniff.

## Processing and persistence

- Media commands use fixed arguments, never a shell or user-provided command fragments. Context cancellation terminates Unix process groups or the complete Windows job. Windows processes join their private job while the primary thread is suspended, before tool code can spawn descendants. Output bytes, duration, transfer bytes, time and FFmpeg threads are bounded. HLS import requires measured full-manifest duration to agree with provider metadata within 1 second. Local remux presentation offsets preserve the original timeline and A/V delay; separate HLS renditions are refused rather than assuming synchronisation.
- Up to 64 HLS continuity periods may be remuxed separately after initialization-map changes or timestamp resets. Codec parameters and extradata hashes must match. Concatenation accepts only generated relative filenames for local normalized Matroska files, with `safe=1`, the file protocol and a fixed demuxer whitelist. No upstream manifest text or URL reaches the concat demuxer. Aggregate downloads, normalized files and temporary segment copies remain within the reserved two-input staging bound.
- FFprobe/FFmpeg cap input streams at 32, decoded frame pixels at 33,554,432 (including 8K), individual allocations at 256 MiB and decoder threads at the configured bound. These tool limits supplement the container memory limit; they are not a total process RAM quota. Inspect stdout stops the process group immediately above 8 MiB; stderr retains at most 16 KiB. Neither writer embeds bytes.Buffer, whose ReadFrom shortcut previously bypassed bounded Write through io.Copy.
- The local engine validates profile/thread/byte/timeout configuration and defaults to 2-minute inspection and 30-minute export deadlines. Relative input filenames are resolved before invoking tools, including names starting with a dash. Destination hard-link and synchronization support is checked before encoding. An output is linked exclusively after successful validation and cancellation checks; file data and required directory entries are synchronized before acknowledging success within an already persistent directory hierarchy. If directory synchronization fails after linking, the final name is retained and an explicit uncertain-publication diagnostic is returned. Existing outputs are never replaced or unlinked during uncertainty recovery. Private temporary workspace cleanup is attempted on return.
- Worker leases expire; stale workers cannot update state or register artifacts after takeover. Shutdown/lost lease access leave unfinished work recoverable within the existing attempt limit, including interruption during publication; completed outputs are retained. User cancellation wins concurrent failures for pending items. Final database reads/writes have five-second bounds.
- API database stages have five-second bounds including connection-pool acquisition and SQL lock waits, with independent bounded rollback cleanup. Media transfers keep their own budgets. Database unavailability returns a fixed HTTP 503 diagnostic; uncertain mutation COMMIT outcomes remain possible and require safe replay/recovery rather than blind retries.
- New uploaded/direct sources, thumbnails, window previews and artifacts publish from private staging names and synchronize completed files and required directory entries before database registration. Service-created directory chains complete their persistence barriers, including retries after an interrupted creation. Synchronization failure cannot register a successful result; uncertain source/preview/artifact COMMIT outcomes retain files and their charge for recovery. This requires a storage/filesystem stack that honors synchronization. See the [publication guarantees](operations.md#output-publication-guarantees).
- Startup uses immutable ordered migrations and checks managed schema structure and checksums before DDL. Unknown or inconsistent schemas fail with a stable redacted diagnostic; current-schema restarts perform no DDL. Historical releases lack this guard and require explicit compatibility testing before rollback. See the [migration policy](migrations.md).
- The independent worker health command checks a private, empty local temporary marker refreshed only after successful queue claims/idle queries or active lease heartbeats. It resets on startup, expires after 30 seconds and is removed on shutdown. Do not put this marker on shared media storage.
- Export item error codes and messages use fixed public diagnostics. Subprocess stderr remains private; unknown failures do not invent retry causes or authorize automatic media retries. Stream selection ranks only complete supported input pairs; unsupported separate HLS clocks remain refused.
- Artifacts and sources expire through worker cleanup or the independent maintenance command. Active jobs pin resources. Terminal jobs without retained artifacts are removed, allowing source cleanup. Owner-scoped deletion refuses active sources; its database tombstones survive failures and restarts until physical deletion succeeds.
- PostgreSQL reservations, byte counters and queue leases coordinate independent API/worker processes. The IP rate limiter is process-local, so the current deployment uses one API; adding API replicas requires a shared IP limiter. One worker process runs a configurable pool of 1–8 jobs. Unknown or larger-than-8,388,608-pixel video inputs acquire the entire local processing pool; this scheduling bound supplements the container memory quota.
- Application limits are admission limits, not a filesystem quota: apply a real volume/disk quota and memory/CPU/PID limits too. The supplied Compose example drops API/worker capabilities and sets memory, CPU and PID limits. For production, also configure a read-only root filesystem and bounded writable temporary filesystem alongside the media volume. Leave room for PostgreSQL, logs, and operating-system updates.
- Old unregistered artifact/source files left by a crash between disk publication and database registration are adopted into the durable ledger and reconciled in bounded batches. A timeout/retention floor prevents cleanup from racing active writes. Failed physical deletion keeps bytes charged; reclaimed worker leases retain separate reservations until their old workspaces can safely be removed.

Do not log session cookies, signed CDN links, passwords, or raw subprocess output in public responses. Sensitive data should not be committed to this repository. See [SECURITY.md](../SECURITY.md) for reporting.

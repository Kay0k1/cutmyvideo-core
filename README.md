# cutmyvideo-core

**Нарезка видео и аудио для приложений, скриптов и автоматизации.**

[![Core checks](https://github.com/Kay0k1/cutmyvideo-core/actions/workflows/ci.yml/badge.svg)](https://github.com/Kay0k1/cutmyvideo-core/actions/workflows/ci.yml)

**Русский** · [English](README.en.md) · [Документация](docs/README.md) · [Релизы](https://github.com/Kay0k1/cutmyvideo-core/releases) · [Сайт](https://cutmy.video)

Выберите интервалы из записи и получите отдельные клипы, один объединённый файл или подборку самостоятельных собранных клипов. Движок написан на Go и использует FFmpeg для обработки медиа. Его можно встроить в Go-приложение, вызвать через CLI или подключить по HTTP. [cutmyvideo-web](https://github.com/Kay0k1/cutmyvideo-web) — отдельный браузерный редактор, использующий это ядро.

## Выберите способ использования

| Задача | Интерфейс | Что нужно при запуске |
| --- | --- | --- |
| Нарезать локальные файлы | [CLI](docs/usage.md#cli) | `cutmy`, FFmpeg и ffprobe |
| Встроить движок в Go | [`pkg/engine`](docs/usage.md#go-library) | Go-приложение, FFmpeg и ffprobe |
| Вызывать из Python или TypeScript | [SDK](docs/sdk.md) | Для локальной работы — CLI и медиаинструменты; для HTTP — адрес сервера |
| Предоставить API с очередью заданий | [Свой сервер](docs/self-hosting.md) | API, обработчик, PostgreSQL и хранилище медиа |

Локальная нарезка работает без базы, учётных записей и HTTP-сервера. SQL относится к серверному хранению заданий; TypeScript — к клиентскому SDK. Разделение компонентов и зависимостей описано в [архитектуре](docs/architecture.md).

## Быстрый старт: локальный файл

Установите FFmpeg/ffprobe с libx264, AAC и libmp3lame. Используйте проверенный релизный бинарник или соберите текущие исходники с Go 1.26.9+ (CI и релизы используют 1.27.2):

```sh
git clone https://github.com/Kay0k1/cutmyvideo-core.git
cd cutmyvideo-core
go build -trimpath -o cutmy ./cmd/cutmy
./cutmy version
./cutmy inspect --input interview.mp4
./cutmy clip --input interview.mp4 \
  --start 00:00:05 --end 00:00:15 --output quote.mp4
```

Результат — JSON с путём, размером и фактическими границами. Существующий файл сохраняется. Точный режим перекодирует выбранный участок; `--mode copy` сохраняет совместимые исходные потоки и может начать с предыдущего ключевого кадра. На Windows запускайте `cutmy.exe`. [Настройки, ошибки и ограничения](docs/usage.md).

### Несколько клипов и проверка задания

Для ядра 1.3.0 или текущей сборки из исходников:

```sh
cp examples/cuts.json cuts.json
# Измените input и интервалы в cuts.json под свою запись.
mkdir clips
./cutmy preflight --plan cuts.json --output clips
./cutmy batch --plan cuts.json --output clips
```

Пути `input` разрешаются относительно файла плана. Для объединения задайте `"output_mode": "joined"` и передайте имя результата вместо каталога. Проверка возвращает выполненные и отложенные проверки; она не создаёт медиа и не гарантирует успешное декодирование или итоговый размер. [Планы, preflight и объединение](docs/batch-cutting.md).

### Самостоятельные клипы и черновики

Сохраните подборку с постоянными ID клипов и упорядоченными фрагментами внутри каждого клипа. Проверьте план, соберите черновой MP4 и после правок экспортируйте выбранные ID. Кадрирование и выбор звука каждого клипа сохраняются в финальной сборке. Go, CLI и HTTP возвращают соответствия исходных и выходных интервалов.

[Руководство по подборкам](docs/clip-collections.md) · [Рабочий цикл ИИ-агента](docs/agent-workflow.md)

## Python и TypeScript

Оба SDK поддерживают цикл **проверить задание → запустить → получить результат** локально и через API. Есть типизированные ошибки, частичные результаты, отмена, ожидание и потоковая передача файлов. Во время выполнения SDK не требуют сторонних библиотек; обработка видео остаётся в Go/FFmpeg.

Планы — обычный JSON, пригодный для редактора, сервиса или автоматизированного помощника. Раннер коллекции сохраняет приватное состояние и ключ идемпотентности сам; для отдельных HTTP-заданий это делает вызывающая сторона.

[Установка и примеры](docs/sdk.md) · [Python](sdk/python/README.md) · [TypeScript](sdk/typescript/README.md)

## Свой HTTP-сервер

Локальный пример запускает PostgreSQL, API и обработчик с общим томом медиа:

```sh
umask 077
printf 'POSTGRES_PASSWORD=%s\n' "$(openssl rand -hex 24)" > .env
docker compose --env-file .env -f deploy/compose.example.yml up --build -d
curl --fail http://localhost:8080/readyz
```

API слушает `127.0.0.1:8080`. Пример использует уменьшенные лимиты для разработки. Для публичной установки используйте [руководство по HTTPS-размещению](docs/self-hosting.md); настройки, резервные копии и обновление описаны в [документации](docs/README.md#сервер-и-эксплуатация).

## Возможности и границы

- Именованные интервалы, отдельные файлы и объединение в заданном порядке, включая повторяющиеся участки.
- Редактируемые подборки клипов, черновые MP4-сборки, кадрирование каждого клипа и повторный экспорт выбранных ID.
- MP4 H.264/AAC, MP3, копирование совместимых потоков в MP4/MKV; выбор аудиодорожки и текстовых субтитров.
- Кадрирование точного MP4, учёт поворота и пропорций пикселей, ограниченные предпросмотры и звуковая волна.
- Локальные файлы, загрузки через API, прямые HTTPS-файлы и поддерживаемые публичные записи через yt-dlp.
- На сервере: постоянная очередь, приватные сессии, идемпотентность, отмена, восстановление и ограничения ресурсов.

Точный экспорт сохраняет заданные настройки качества, но перекодирование не означает побайтового совпадения с оригиналом. Copy сохраняет совместимые потоки с фактическими границами по пакетам/ключевым кадрам. [Политика медиа](docs/media.md) описывает дорожки, геометрию и цвет.

Распознавание площадки не гарантирует доступность каждого ролика. Прямой HTTPS-файл скачивается целиком; поддерживаемые прогрессивные и завершённые HLS-записи могут читаться по выбранным участкам. Текущие эфиры, DRM и закрытые записи отклоняются. [Провайдеры и ограничения](docs/providers.md).

Измеренные ускорения относятся к конкретным воспроизводимым сценариям: [методика и результаты](docs/performance.md). Поддержка ОС и обязательные проверки выпуска — в [описании платформ](docs/platforms.md).
